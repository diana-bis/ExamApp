================================================================
  E-TEST SYSTEM — TECHNICAL SPECIFICATION
================================================================

PROJECT OVERVIEW
----------------
A React-based exam management system with a mock in-memory backend.
The architecture is layered so that swapping to a real backend
requires only a single config flag change (isMockMode).

Original requirement: Design and implement a Full Stack web application
for managing online exams and student submissions, supporting lecturers
and students with authentication, persistent storage, and cloud deployment.

================================================================
DATA MODELS
================================================================

User
----
  id          : string   e.g. "U001"
  username    : string   unique, case-insensitive lookup
  password    : string   plaintext (mock only)
  name        : string   display name
  role        : string   "teacher" | "student"

Exam
----
  id            : string     e.g. "EX001"
  title         : string
  status        : string     "draft" | "published"
                             New exams default to "draft".
                             Students can only access published exams.
  timeLimit     : number     minutes
  passingGrade  : number     percentage (0–100)
  questions     : Question[]

Question
--------
  id            : string
  type          : "MULTIPLE_CHOICE" | "OPEN_ENDED"
  text          : string

  MULTIPLE_CHOICE only:
    options       : string[]   answer choices
    correctAnswer : string     must match one of options

  OPEN_ENDED only:
    (no extra fields — pending manual review)

Submission
----------
  id          : string   e.g. "SUB1716384721234"
  studentId   : string   references User.id
  examId      : string   references Exam.id
  answers     : object   { [questionId]: string }
  grade            : number   percentage (0–100), auto or teacher-overridden
  feedback         : string   teacher's written feedback (optional)
  resultsPublished : boolean  true = student can see grade/feedback;
                              auto-true for MC-only exams, false for OE exams
                              until teacher publishes
  submittedAt      : string   ISO 8601 timestamp (set server-side)


================================================================
GRADING LOGIC
================================================================

  - Only MULTIPLE_CHOICE questions are auto-graded.
  - OPEN_ENDED answers are stored but not scored (pending review).

  grade = (mcCorrect / mcTotal) * 100   rounded to nearest integer

  Pass condition: grade >= exam.passingGrade

  If mcTotal == 0 (all open-ended), grade defaults to 0.


================================================================
SERVICE LAYER
================================================================

ConfigService
  getAppName()        → "E-Test System"
  getApiBaseUrl()     → "/api"
  getDefaultRole()    → "teacher"
  isMockMode()        → true | false
                         Controls mock vs real API globally.

AuthService
  login(username, password)             → Promise<User>
  register({ name, username,
             password, role })          → Promise<User>
  logout()                              → Promise<void>
  getCurrentUser()                      → User | null  (sync)
  getUsers()                            → Promise<User[]>

  Session stored in localStorage via StorageService.
  Field-specific errors: error.field = "username" | "password"

NotifyService
  notifySuccess(message)
  notifyError(message)
  notifyInfo(message)

  Bootstrap alert toasts, bottom-right, auto-dismiss 3.5s.

LoggerService
  log(...args)
  warn(...args)
  error(...args)
  getHistory()    → last 50 entries [ { level, time, message } ]
  clearHistory()

  Prepends [LOG/WARN/ERROR HH:MM:SS] to every console call.

StorageService
  saveItem(key, value)    serialises to JSON
  getItem(key)            deserialises from JSON
  removeItem(key)

  Used only by AuthService for "current_user" key.

================================================================
MOCK DATABASE
================================================================

Singleton class (MockDatabase) — one shared instance across all
services. State lives in this.data:

  this.data.users       : User[]
  this.data.exams       : Exam[]
  this.data.submissions : Submission[]

Seed data:
  Users:  teacher / password (Bob), student / password (John)
  Exams:  "JavaScript Basics" (EX001), "React Fundamentals" (EX002)

Methods:
  findUser(username)       case-insensitive
  addUser(user)
  findExam(id)
  addExam(exam)
  updateExam(id, updates)
  deleteExam(id)
  addSubmission(submission)
  getSubmissions()
  getSubmissionById(id)

================================================================
SESSION MANAGEMENT
================================================================

  - Login stores a User object in localStorage under "current_user".
  - App.jsx initialises user state from authService.getCurrentUser()
    on load, so sessions survive page refresh.
  - Logout removes the key and resets React state.
  - Registered users are added to mockDb only (lost on page refresh).


================================================================
EXAM TIMER
================================================================

  - Timer starts when exam data finishes loading in TakeExam.jsx.
  - Counts down from exam.timeLimit * 60 seconds.
  - Badge colour: white → yellow (≤60s) → red (≤30s).
  - On expiry: auto-submits current answers, skips MC validation.
  - answersRef (useRef) ensures the auto-submit closure always
    reads the latest answers state without stale capture.


================================================================
ID GENERATION  (mock mode)
================================================================

  Users:       "U" + Date.now()
  Exams:       "EX" + zero-padded sequential number  e.g. EX003
               (derived from highest existing numeric suffix)
  Submissions: "SUB" + Date.now()
  Questions:   "q"  + Date.now()  (within form, client-side only)


================================================================
SWITCHING TO A REAL BACKEND
================================================================

  1. In ConfigService.js:
       isMockMode() { return false; }
       getApiBaseUrl() { return 'https://your-api.com/api'; }

  2. No other changes required. All ExamService, SubmissionService,
     and AuthService methods have fetch() branches already wired.

  3. The real backend must:
       - Accept/return the same JSON shapes as the data models above.
       - Set submittedAt server-side on POST /submissions.
       - Assign exam IDs server-side on POST /exams.
       - Return field-specific errors for auth failures
         so LoginPage and RegisterPage can highlight the right field.
